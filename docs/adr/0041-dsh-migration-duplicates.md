# ADR-0041 dsh 格式迁移造成的重复计数:dedup_key + 并列时按 event_id 决胜

状态:已采纳(2026-10-30)

## 背景

ADR-0040 的调研发现:dsh 升级日志格式时,会把旧会话复制成新格式文件,**旧文件保留不删**。
本机 324 个会话文件里有 8 个目录新旧格式并存,OmniToken 两个都读(`*.jsonl.zstd`)。

逐行对照(只比 session id、`seq`、`time`、四个 token 分量,不看内容):

| 迁移 | 旧文件每行在新文件里找到的副本 | 其中 `seq` 不变 | 时间被改 | 找不到 |
|---|---|---|---|---|
| v1 → v3 | 221 / 221 | 0 | 0 | 0 |
| v3 → v4 | 2,573 / 2,573 | 2,573 | 0 | 0 |

- v3 → v4 保留了 `seq`,`event_id` 相同,ADR-0004 的幂等已经把它们去掉了。
- **v1 → v3 重编了 `seq`**,`event_id = f(session_id, seq, 用量)` 随之变了:**221 行被计了两次**,
  多出 261,693 个 output token、共 62,640,178 个 token(dsh 全部用量的 1.70%)。
- 副本与原件的 session id、`time`(毫秒)、四个 token 分量逐字相同;用实际解析器对照,
  model / provider / cwd / `gen_ms` / `ttft_ms` 也 0 处不同。

这与 ADR-0020 的 Codex 分叉是同一类问题:**一次生成被写进两个文件**,`event_id` 回答的是
「这条日志行见过没有」,回答不了「这次生成记过没有」。

## 决定

### 1. dsh 也产出 `dedup_key`

`dedup_key = "dsg:" + hex(sha1(session_id | time | input | output | cache_read | cache_write)[:12])`

- 只在 session id 非空且 `time > 0` 时产出;缺任一项就不产出,退回只按 `event_id` 去重 ——
  失效方向是「可能重复」而不是「误合」,与 ADR-0020 相同。
- 不含 `seq`(迁移会改它),也不含 turn/step(不保证迁移不动它)。`time` 与用量是实测里
  迁移原样保留的部分。
- 碰撞检验:全部 19,000+ 条事件得到 16,569 个键,有两个 `event_id` 的键恰好 221 个,
  全部是跨文件的迁移副本;同一文件内 0 次碰撞。
- 与 `event_id` 一样,**入库后冻结**:golden 测试钉死具体值(期望值在 Go 之外用 `shasum` 算出)。

### 2. 冲突消解补上并列规则:`ts` 相同时删 `event_id` 大的那条

ADR-0020 §3.3 的规则是「保留 `ts` 小的那条」,依据是 Codex 的 647 个碰撞组里 **0 次并列**。
实现对并列的处理是「后到的算副本」(`e.TS >= ownerTS`)—— 计数对,但**留下哪条取决于到达顺序**,
违背了同一节「判据与扫描顺序无关」的要求。dsh 的副本保留原时间戳,**每一组都是并列**,
所以规则必须补全:

> 两行共享 `dedup_key` 时,删 `ts` 大的那条;`ts` 相同时,删 `event_id`(字典序)大的那条。

- 对 Codex 不改变任何已有结果:它的副本时间戳恒晚于原件,走不到并列分支。
- 对 dsh,两份副本的用量、归属、派生列都相同,留哪条不影响任何数字,要的只是**确定**。

## 与铁律的边界

- **`event_id` 不变**,本决策是在它之上的追加约束(同 ADR-0020)。
- 删除的安全边界不变,只是把并列补成确定的:**只在两行共享同一个 `dedup_key` 时触发,
  只删其中一行**;判据全在库内,与到达顺序无关。CLAUDE.md 对应段落同步修改。
- 删掉的是一次记账错误的产物,它的每个字段都能在留下的那行里逐字找到(ADR-0020 §3.5 的理由照样成立)。

## 回填与实测

历史库里两份副本都在、都没有键。agent/serve `-rescan` 重新读到两个文件时,先到的那条把键
回填上,后到的撞上唯一索引,按上面的规则消解 —— 与 ADR-0020 §3.4 同一条路径。迁移留下的
都是不再增长的旧文件,**只有 `-rescan` 能触发**(见 `docs/configuration.md`)。

用全部本机 dsh 历史在真实 store 上回放(先按旧解析器写入不带键的历史,再重扫两遍):

| 扫描顺序 | 第一遍 | 第二遍 | 留下的 event_id 集合 |
|---|---|---|---|
| 正序 | 删 221 行,output −261,693,总 token −62,640,178 | 0 变更 | 两种顺序完全相同 |
| 逆序 | 同上 | 0 变更 | |

**混合版本是安全的**:只升级 agent(带键)而 Hub 还是旧版 → 并列按旧实现「后到的算副本」,
计数照样正确,只是留哪条看顺序;只升级 Hub 而 agent 还是旧版 → 没有键,与今天等价。

## 未做

- 若某个旧格式文件被删掉、只剩新格式副本,那就只有一份,本来就不重复,无需处理;
  反过来只剩旧文件同理。

背景:ADR-0004(event 身份)、ADR-0020(分叉重复)、ADR-0029(dsh 解析器)、ADR-0040(dsh 速度)。
