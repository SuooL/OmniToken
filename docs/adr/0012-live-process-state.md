# ADR-0012 活跃会话的地面真值:agent 侧读本机进程表

状态:已采纳(2026-07-29,与用户确认)

## 背景

面板上的「活跃会话」是**推断**出来的:最近 10 分钟有事件就算活跃。这个代理指标
分不清两件事 ——

- 会话开着,但你在读代码、在想、在等工具跑,十分钟没产生 token;
- 会话三分钟前已经关掉了。

两者在日志里长得一模一样。调研 abtop 时看到它走的是另一条路:直接读本机进程表,
知道哪些 agent CLI **此刻真的在跑**。那是地面真值,不是推断。

我最初反对过这条路,理由是「服务端看不到远端进程」。**那个理由是错的** ——
采集本来就是分布式的,agent 就跑在每台被监控的机器上,读本机进程表完全正当。

## 决策

**agent(以及服务端的本机采集器)读本机进程表,上报「正在运行的 agent 会话」,
作为 events / quotas 之外的第三种载荷。**

### 为什么不进 events 表

这是本决策最重要的一条。ADR-0004 的事件模型建立在三个前提上:事件不可变、有
event_id、重复观测要**去重**。进程状态三条都不满足:

- 它是**瞬时状态**,不是发生过的事;
- 没有天然的 event_id,PID 会被系统复用;
- 重复观测的正确语义是**覆盖**,不是去重 —— 同一个 PID 第二次被看到,
  说明它还活着,而不是我们数重了。

把它塞进 `events` 会污染那张表的语义,并让「token 只计一次」这条铁律变得难以论证。
因此单独一张 `live_sessions` 表,按 `(device, pid)` 覆盖写入。

### 陈旧数据靠 TTL,不靠删除

一台机器断线后,它上报过的行会永远留着。读取时按 `observed_at` 过滤(与配额同一
思路),而不是让上报方负责清理 —— 上报方可能正是那台已经离线的机器。

### v1 的范围

只报**正在运行的 agent CLI 进程**:pid、工具(claude / codex)、启动时间。

**不做**子进程树、监听端口、cwd 归属。理由:

- 子进程与端口是 abtop 的核心价值(它是本机 TUI),而 OmniToken 是跨设备的用量
  账本,这些数据在跨设备聚合视图里价值低得多;
- cwd 在 Linux 上是免费的(`/proc/<pid>/cwd`),但 macOS 需要额外 shell 出 `lsof`,
  会让「有没有 repo 归属」变成平台相关的用户可见差异。宁可两个平台一致地没有,
  也不要一个有一个没有。

将来若要补 repo 归属,正确做法是像 abtop 那样读 Claude 自己写的
`sessions/{PID}.json` 拿 session_id,再与已入库事件关联,而不是猜 cwd。

### 什么不算「会话」(实现时对着真实进程表补充)

同一个二进制跑在服务模式下不算会话,靠子命令区分:`app-server`、`mcp-server`、`mcp`。

这条不是推演出来的,是拿本机进程表核对时撞上的:ChatGPT 桌面版与 VS Code 扩展
各自常驻一个 `codex ... app-server`,只要编辑器开着就在;而一个装了 Codex 插件的
**Claude** 会话会拉起 `node .../codex mcp-server` 及其原生子进程 —— 照单全收的话,
一个 Claude 会话会被记成两个 Codex 会话,面板上则永远挂着「codex 正在运行」。
那正是本决策想要消灭的无信息量信号。

同理,判断二进制名是**大小写敏感**的:ChatGPT.app 的辅助进程路径里有一段
`Codex Framework.framework`,大写的 C 是它与 CLI 之间唯一的区别。

## 平台策略

这是项目里**第一段平台相关代码**,所以定个规矩:

| 平台 | 做法 |
|------|------|
| Linux | 直接读 `/proc`,纯 Go,无外部依赖 |
| macOS / 其它 Unix | `ps -axo pid,lstart,command`,与 abtop 同一选择 |
| Windows | 暂不支持,返回空;不报错 |

在 macOS 上 shell 出 `ps` 与 N1(单二进制、无 CGO、可交叉编译)不冲突:`ps` 是每台
Unix 都有的基础工具,而引入一个跨平台进程库(gopsutil 之类)会带来大得多的依赖树。
Windows 返回空而不是报错,是因为**没有实时会话数据**不该让整个采集失败。

## 后果

- 面板能区分「开着但空闲」与「已经关掉」,这是当前用推断做不到的;
- 新增一张表、一种载荷、一段平台相关代码 —— 都是新的维护面;
- SSH 拉取的设备(ADR-0003 的「远端零安装」)**拿不到实时会话**,因为那些机器上
  没有 agent。面板必须把「无数据」和「没有会话在跑」区分开,不能把前者显示成后者。
