# ADR-0016 读接口鉴权由监听地址推导,默认监听改回 loopback

状态:已采纳(2026-07-30,与用户确认)。修订 [ADR-0008](0008-desktop-client.md) 依赖的
「所有读接口都是免鉴权的」这个前提,以及它「只存地址不存 token」的待办条款;
瘦客户端、Tauri 外壳、网络走 Rust 侧、服务端不发 CORS 头四条全部不变。

## 背景

给 macmini 装上第二台设备、准备真机验多设备汇集时,才看清一件事:多设备汇集与
ADR-0008 当时依赖的安全前提是**直接冲突**的,不是先后关系。

ADR-0008 为「为什么不给服务端加 CORS」写下了这段理由,一字不差:

> 除 `POST /api/v1/ingest` 与设置写入外,**所有读接口都是免鉴权的**。一旦返回
> `Access-Control-Allow-Origin: *`,任何用户访问过的网页都能读取其用量数据,
> 只要能连到该服务端。

那段推理是对的,结论也是对的。问题在于它把「只要能连到该服务端」当成了一个小概率
前置条件 —— 而支撑这个判断的前提当时也写下来了:「服务端只听 127.0.0.1」。

**但默认 `listen` 是 `":8787"`。** 空主机名不是 loopback,是**每一个网络接口**。
所以那句前提从来就不成立:一份全新安装、用户什么都没改,就把自己的全部用量历史
(14 个读接口 + 整个面板 + SSE 流)对同网段任何人公开了。挡在前面的只有一行
`WARNING: no ingest token` 日志 —— 而那句话说的是**写**,读接口无论有没有 token
都照样返回数据,警告与实际暴露面根本不对应。

最坏的形态是:**不安全的那个配置,正是什么都不做就会得到的那个。**

多设备汇集要求服务端能被别的机器连上。到那一刻,ADR-0008 赖以成立的前提就没了。
所以读接口鉴权不是「多设备之后可以再加的加固」,而是**多设备的前置条件**;
PR 顺序上它必须排在真机接 agent 之前。

## 决策

### 1. 读接口要不要凭据,由监听地址推导,不由开关决定

不新增 `require_read_auth` 这类字段。判定完全来自 `cfg.Listen`
(`internal/server/server.go` 的 `readAuth` / `loopbackOnly`):

| 监听地址 | 读接口 |
|---|---|
| 仅 loopback(`127.0.0.1` / `localhost` / `[::1]`) | 免鉴权,零配置 |
| 可被其它机器访问 + 配了 `token` | 与 ingest 同一个 bearer token |
| 可被其它机器访问 + 没配 `token` | **启动即拒绝**,绝不以开放状态提供服务 |

推导而非开关,是因为这条规则真正要防的是**遗忘**。一个需要人记得打开的安全开关,
在「改一行 listen 去连第二台机器」这个场景里一定会被漏掉 —— 旧的默认值
(`:8787` + 免鉴权读)就是这个失效模式已经发生过一次的证据。

同时它保住了单机场景:只听 loopback 时 `readAuth` 直接返回原 handler,面板、
statusline、桌面端全部不需要任何配置就照旧工作。这是最常见的用法,不能被回归。

14 个读接口**全部**套上 `readAuth`,包括在 loopback 下等价于没套。这样做的价值不在
运行时,在于**将来新加一个端点时不会漏**:漏掉包装比漏掉一个开关更难被发现。

### 2. 默认 `listen` 从 `":8787"` 改为 `"127.0.0.1:8787"`

让「能被别的机器连上」成为一个**刻意的动作**,而不是默认状态。

这是本 ADR 唯一的破坏性变更,后果一节单列。

### 3. 空主机名算「所有接口」,不算 loopback

`":8787"` 的 host 是空字符串。把它读成 loopback 会**静默地**把面板送上网络 ——
静默是最糟的失败形态,所以这条不靠推理,靠一个写死的用例钉住
(`auth_test.go` 的 `TestLoopbackOnly`,`":8787"` / `"0.0.0.0:8787"` / `"[::]:8787"`
均判为非 loopback)。地址解析失败时同样按最坏情况处理,不按最方便的情况处理。

### 4. `GET /api/v1/health` 保持免鉴权,并新增 `auth_required`

它不携带任何用量数据,而且它是客户端用来**区分「地址错了」和「令牌错了」**的唯一
手段 —— 这两件事的修法完全不同,一个裸的连接失败或裸的 401 说不清是哪一个。

响应从 `{"status":"ok"}` 变为 `{"status":"ok","auth_required":<bool>}`。
web 面板启动时探一次:若服务端要 token 而本浏览器没有,就在顶部挂一条横幅指向
**设置 → 访问令牌**。没有这一步的话,用户看到的是九个页面九条一模一样的 401,
且没有任何线索说明该去哪里修。

### 5. 面板外壳(`GET /`)保持免鉴权

浏览器在首次导航时**没有办法带一个头**。要么外壳开放,要么用户只能靠
`WWW-Authenticate` 弹框 —— 而那个弹框拿不到 localStorage 里的令牌,也没法引导。

静态文件里没有任何私有内容:HTML、CSS、JS 全是空壳。真正的数据在此之后的每一次
XHR 里,而那些都走 `readAuth`。所以开放的是壳,不是内容。

401 仍然带上 `WWW-Authenticate: Bearer realm="omnitoken"`,让直接 curl 或直接开
API 地址的人至少得到一个明确的信号,而不是一个没有下一步的 401。

### 6. `?access_token=` 只在 `/api/v1/stream` 上被接受,别处一概不认

浏览器的 `EventSource` **不能设请求头**。这不是没想到别的写法,是这个 API 本身
没有这个能力 —— SSE 要么让令牌走 query,要么在浏览器里根本没法鉴权。

URL 里的令牌确实比头里的差:它会进访问日志、会进 `Referer`。所以处理方式是
**把这条较弱的通道限死在需要它的那一个端点上**,让它不能被用来访问另外十三个。
`queryTokenOK` 只被 `readAuthStream` 调用,而 `readAuthStream` 只包了 `/stream`。

桌面端**完全不用它**:它的流跑在 Rust 里,Rust 能设头(ADR-0014 那条 SSE 桥),
所以它用 `bearer_auth`。较弱的通道只给真正没有别的选择的那一侧。

### 7. 一个令牌,不是两个

`cfg.Token` 是单一共享秘密,同时用于 ingest、设置写入,现在再加上读。

不拆成读令牌与写令牌,因为**这个产品只有一个用户**。ADR 层面的非目标里写得很清楚:
不做多租户/团队权限体系(需求 2 节)。两个令牌能表达的区别(某人只能看不能改)
在单用户系统里没有对应的现实场景,换来的只是两处要同步的配置。

web 面板因此复用设置页**本来就有**的那个 localStorage 键 `omnitoken.token`,
不新开一个输入框。新开一个框就等于造了两份同一个字符串的副本,而副本的问题从来
不是「有副本」,是它们会漂移(ADR-0014 已经在设计令牌上吃过一次这个教训)。
设置页的标题也从「写入令牌」改成「访问令牌」—— 它的作用范围确实变了。

### 8. 桌面端开始存 token(修订 ADR-0008)

ADR-0008 的 `desktop/src-tauri/src/settings.rs` 开篇写着「只存地址不存 token ——
读接口本就免鉴权」。第 1 条一落地这句话就不成立了:一个**指向远端服务端**的菜单栏
客户端,定义上就是「服务端可被别的机器访问」这个场景本身。

**令牌与地址并列,明文存在应用配置目录里。** 这是一个有意的、有边界的选择:

- 它是一个局域网/组网内的 bearer 凭据,同一个字符串用户还会粘进浏览器的
  localStorage —— 那边同样是明文,在这边上 Keychain 不会改变整体的暴露面;
- Keychain 会带来一次授权弹窗和一个平台依赖,而**不改变谁能读到这个文件**:
  任何以该用户身份运行的进程本来就能读。

所以选择是「写进文档」,不是「藏起来」。ADR-0008 的待办里那句「Tauri 有安全存储
能力,不落明文」在此被显式否决 —— 它当时是一句未经权衡的期望。

### 9. 前端只把 path 交给 Rust,地址与令牌都留在 Rust 侧

`api_get` 的签名从 `(base, path)` 改为 `(path)`:webview 不再传地址,也从不持有令牌,
每次请求的凭据都在 Rust 侧挂上。

理由与 ADR-0008 让 HTTP 走 Rust 是同一条,只是更进一步:**webview 拿不到的东西,
就不可能被渲染进某个字符串或某条错误信息**。一个前端不需要看见的秘密,就不要递给它。

## 为什么不是「保持警告」

这是本决策里最需要说清的一条,因为它看上去更温和。

警告已经试过了,而且失败得很彻底:旧默认值就是「所有接口 + 免鉴权读 + 一行日志
警告」这个组合。它的实测效果是,一份默认安装公开了全部用量历史,而唯一的提示
说的还是另一件事(写接口)。**一行没人看的日志不构成任何保护。**

所以「可达 + 无 token」的处理是 `requireAuthConsistency` 返回错误,进程退出码 1,
并且这个检查放在**采集器启动和端口监听之前** —— 一个配错的服务端不该写下任何一行,
也不该接受任何一次请求。

错误信息里必须直接给出两条修法,而不是只说「不安全」:

```
listen="0.0.0.0:8787" 可被其它机器访问,但没有配置 token —— 读接口会把全部用量数据对外公开。
  二选一:
    1) 配 "token": "<随机串>"(读写都要它,面板与桌面端在设置里填同一个);
    2) 改回 "listen": "127.0.0.1:8787",让其它机器经 SSH 反向隧道或中继上报(ADR-0003)
```

## 为什么不是「放到反代后面」

`docs/architecture.md` 原来的说法是「查询 API 面向内网/组网,暴露公网时应置于反代
鉴权之后(文档明示,不在本体造轮子)」。这条对**公网**仍然成立 —— 我们确实不打算
在本体里做 TLS、限速或多用户。

但它答不了这次的问题。多设备汇集的常态是同一个内网或同一个组网(N2),这种场景下
要求用户先立一个 nginx 才能看自己的用量,与「scp 一个文件 + systemd unit」的部署
定位(ADR-0002)完全不成比例。而且「应该放在反代后面」是一句**建议**,建议和警告
一样,拦不住默认值。

一个 bearer token 的常量时间比较是十几行代码,`auth` 里本来就有。这不是造轮子。

## 为什么不做 CORS

不变,理由与 ADR-0008 一致 —— 但值得记下的是,**这条决策让当年那个理由更强而不是
更弱**。ADR-0008 拒绝 CORS 是因为读接口免鉴权;现在读接口有鉴权了,看上去限制可以
放松。不能:面板外壳是免鉴权的(第 5 条),`?access_token=` 会进 `Referer`
(第 6 条),而 `Access-Control-Allow-Origin: *` 会把这些边界全部作废。
桌面端走 Rust 的做法一行都不用改。

## 拓扑不需要新机制

写下这一节的目的是防止有人为了「让第二台机器连上」发明第四种传输方式。
ADR-0003 的四条已经覆盖全部情形,本决策只是给其中每一条补上了鉴权语义:

| 情形 | 用 ADR-0003 的哪一条 | 服务端 listen | 读接口 |
|---|---|---|---|
| 内网可直达 | 第 1 条(agent 只出站,目标就是一个 URL) | 监听内网地址 | 要 token |
| 不可直达,可组网 | 第 1 条,URL 填组网虚拟 IP(Tailscale/EasyTier) | 监听组网地址 | 要 token |
| 只能经某台同伴 | 第 3 条(无状态中继 `relay_listen`,支持链式 d→c→server) | 视中继落在哪一侧 | 要 token |
| 不允许装东西 / 想保持只听本机 | 第 2 条(SSH 拉取)或 SSH 反向隧道 | `127.0.0.1:8787` | **免鉴权** |

最后一行值得单说:SSH 反向隧道让服务端可以继续只听 loopback,由 SSH 本身承担鉴权
与加密。对不想管令牌的人,这是比配 token 更强的选择,而且它复用的是用户既有的
SSH 通道 —— 与 ADR-0003 第 2 条同一条理由。

具体配置写在 `docs/configuration.md` 的「多设备怎么配」。

## 实测(真机 curl,2026-07-30)

不是推演,逐条跑过:

| 场景 | 结果 |
|---|---|
| 可达 + 无 token 启动 | 退出码 1,打印二选一的错误信息 |
| `/api/v1/live` 不带 token | 401,带 `WWW-Authenticate: Bearer realm="omnitoken"` |
| `/api/v1/live` 带错 token | 401 |
| `/api/v1/live` 带对 token | 200 |
| `/api/v1/overview` 三种 | 同上 |
| `/api/v1/stream?access_token=<对>` | 200 |
| `/api/v1/stream?access_token=<错>` | 401 |
| `/api/v1/live?access_token=<对>` | **401** —— query 兜底确实只在 stream 上生效 |
| 面板外壳 `GET /` | 200 |
| 回归:只听 loopback、不配 token | `/live`、`/overview`、`/stream` 全 200;`health.auth_required=false` |

倒数第三行是这次最想验的一条:`?access_token=` 是一个刻意开的小口子,必须确认它
没有变成一个绕过整套读鉴权的通用参数。

## 后果

**破坏性变更(必须显眼)**

**配置文件里显式写了 `"listen": ":8787"` 的部署,升级后会启动失败。** 默认值的改动
救不了它们 —— 显式值优先。命中的是「装的时候把生成的默认值留在那儿没删」这类部署,
也就是相当一部分现有安装。

修法就是启动错误里印的那两条:配一个 `token`,或者把 `listen` 改成 `127.0.0.1:8787`
再用隧道/中继。这被判为**可接受**,因为:

- 失败是响亮的、发生在启动瞬间的,并且错误信息直接给出两条可执行的修法;
- 替代方案是「静默保持不安全」,而那正是这个 ADR 要消灭的东西;
- 这是一次单用户自持有的部署 —— 修一次,而不是协调一次迁移。

**正面**

- 一份全新安装不再向网络公开任何东西,而且这个结果不依赖用户读日志或记开关;
- 多设备汇集从此有一个安全的落地方式,这是 PR2/PR3 真机接入的前置条件;
- 单机场景零回归:仍然零配置,`readAuth` 在 loopback 下退化为原 handler;
- 读与写共用一个令牌、一个输入框、一个 localStorage 键,没有可漂移的第二份;
- 加新读接口时忘记包 `readAuth` 会立刻表现为「可达时也不鉴权」,而不是悄悄留个洞。

**负面**

- 「读接口免鉴权」这句话散落在若干注释与文档里(`docs/API.md`、
  `docs/architecture.md` 第 6 节、ADR-0008 的 CORS 一节、桌面端 `settings.rs`
  的文件头)。代码侧已随本次改动更新,文档侧按 ADR 惯例**不改写历史 ADR**,
  但 `API.md` 与 `architecture.md` 是现状描述而非历史记录,需要单独跟一次。
- 桌面端多了一个明文存的凭据。它在配置文件里(权限随 Tauri 的 app config dir),
  这是第 8 条明确接受的代价,不是遗漏。
- `?access_token=` 会出现在服务端访问日志与可能的 `Referer` 里。范围已限死在一个
  端点,但它是一个真实存在的、比头更弱的通道,不应被当作等价选项推广。
- 判定依赖 `cfg.Listen` 的字面值。若有人在 loopback 前面自己架了一层端口转发,
  服务端会以为自己只听本机,而实际可达 —— 这种情况下鉴权由那层转发负责,
  与 SSH 隧道同理,但它是一个我们看不见的前提。

**不在本 ADR 范围**

- TLS / 公网暴露:仍按 `architecture.md` 的结论,交给反代,本体不做;
- 令牌轮换与多凭据:单用户系统下没有对应场景,真需要时再单独决策;
- agent 侧的 ingest 鉴权语义不变 —— 未配 token 时接受写入,这是单机零配置上报
  依赖的行为,与读接口按地址推导是**故意不同**的两条规则。
