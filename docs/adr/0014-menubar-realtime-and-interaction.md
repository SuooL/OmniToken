# ADR-0014 菜单栏客户端:实时改用 SSE 桥,交互与视觉对齐系统与面板(修订 ADR-0008)

状态:已采纳(2026-07-30,与用户确认)。修订 [ADR-0008](0008-desktop-client.md) 的
第 4 条(「菜单栏 v1 是精简视图」)与它对 SSE 桥接的推迟结论;瘦客户端、Tauri 外壳、
网络走 Rust 侧三条不变。

## 背景

ADR-0008 落地的是 v1:能看、能设地址、托盘有表盘。之后 M5 把重心整体转向实时,
web 面板连版式一起重做了 —— 菜单栏没跟上。今天拿 v1 逐条核对,缺的不是打磨,
是三类结构性的东西。

**一、托盘没有菜单。** `TrayIconBuilder` 从头到尾没调过 `.menu()`,只挂了一个左键
事件。于是**没有退出入口** —— 装上之后想关掉它,只能去活动监视器强杀,或者
`killall OmniToken`。一个常驻菜单栏的程序做不到「从菜单栏退出」,这不是缺功能,
是漏了下限。同样没有的:打开完整面板、开机自启、从菜单进设置。

**二、两条轮询,而且都不实时。** 面板 15s 拉一次 `/api/v1/live`,托盘另起一个线程
60s 拉一次同一个端点。ADR-0008 当时把 SSE 判为「最难桥接的一环」并推迟,
`internal/server/live.go` 里 `handleLive` 的注释也留着这句话。代价现在看得很清楚:

- 同一份数据被请求两次,两个消费者可能显示不同时刻的快照;
- 「实时」在菜单栏上是 15 到 60 秒的滞后。而 M5 的结论恰恰是**实际更需要的是实时**。
  菜单栏是这个产品里最该实时的一个面 —— 它是唯一不需要切窗口就能看见的东西。

**三、弹窗只用了载荷的两个字段。** `/api/v1/live` 给出 `quotas`、`burn`、`speed`、
`sessions`、`processes`、`devices`、`windows`,弹窗只渲染了 `quotas` 和 `burn`。
被漏掉的 `speed` 正是 ADR-0009 定义、M5 定为 P0 的**生成速度** —— 全套指标里最实时、
最该出现在菜单栏的那一个,反而只在浏览器里看得到。

**视觉上则是明确的脱节。** `desktop/ui/style.css` 的开篇注释写着「Colours mirror
web/style.css」,这句话在写下时是真的,现在不是了:M5 之后 web 那边是深色为主的
仪表盘令牌(玻璃层、等宽展示字体、光谱色板),菜单栏还是浅色为主 + `system-ui` +
单一蓝。注释没骗人,是令牌**各自演化**了 —— 这正是「抄一份」这种做法的必然结局。

## 决策

### 1. 实时改为 Rust 侧一条 SSE 长连接,轮询降级为断流兜底

Rust 持有一条 `GET /api/v1/stream`,解析出的每个快照同时喂给四个消费者:webview、
托盘图标、托盘数字、配额预警判定。

**为什么桥在 Rust 而不在 webview**:与 ADR-0008 让 HTTP 走 Rust 是同一个理由 ——
webview 在 `tauri://localhost`,服务端刻意不发 CORS 头。但这里还多一层:托盘图标
本来就只能在 Rust 侧画。让快照在 Rust 落地一次再分发,比让 webview 和 Rust 各自
去拉一遍,请求少一半,而且**两个面不可能显示不同时刻的数字**。

**兜底而不是放弃**:连不上或断流就退回轮询 `/api/v1/live`,重连按 1s→2s→…→30s 退避。
弹窗头部如实标出当前是实时还是降级 —— 「权威优先,推断标注」这条铁律在 UI 上的
同构表达:降级了就说降级了,不能让一个 60 秒前的数字装成实时的。

**静默看门狗(实现期补充)**:比断流更危险的一种失败是**对端停发但不关闭 socket**。
TCP 会把这样的连接一直保持下去,于是弹窗顶着「实时」显示一个永远冻住的数字 ——
正是本条的 mode 指示器想要消灭的那种谎。落地时确实撞到了:一个放弃了响应但没关连接
的服务端让整条桥永久阻塞,而且没有任何察觉手段。

因此加 90 秒静默上限(服务端 30s 心跳的三倍),超时即视为已死并重连。**守时按字节计,
不按解析出的事件计** —— 服务端的 `: hb` 是注释,不产生事件,按事件计时会把一条健康
但安静的连接反复拆掉。

服务端**一行不用改**。`/api/v1/stream` 与 `/api/v1/live` 都已经在,且共用
`livePayload`,所以菜单栏和实时页从定义上就不可能对同一个十分钟报出不同的数。

### 2. 交互模型:左键切换弹窗,右键出菜单

`show_menu_on_left_click(false)`,左键仍走原有的弹窗切换(含那段处理「按下先夺焦、
松开再触发」双事件的去抖,原样保留)。菜单里必须有:打开完整面板、立即刷新、
菜单栏数字(关闭 / 配额% / 生成速度)、配额预警、开机自启、全局快捷键、设置、关于、
**退出**。

菜单栏数字用 `TrayIcon::set_title`。表盘弧只有五档、只答「大概多满」,想知道具体
数字仍得点开;把数字直接印在菜单栏上是这类工具的常规做法,但**默认关闭** ——
菜单栏是稀缺空间,该由用户决定要不要占。

### 3. 视觉用系统原生毛玻璃,不用 CSS 画卡片

弹窗窗口开 `windowEffects: { effects: ["popover"], radius }`,即 macOS 的
`NSVisualEffectMaterial.popover`。原本是一个透明窗口里用 CSS 描一个圆角实心卡片,
远看像,近看是贴上去的:不透背景、不随桌面明暗变化、圆角与系统不同源。

**不做弹窗箭头。** Tauri 只能给矩形窗口,毛玻璃层是整个窗口的属性,没法跟着一个
CSS 三角形走 —— 硬画会在箭头根部留一道接缝,比没有箭头更糟。改为紧贴锚定在图标
下方,与 Ventura 之后多数菜单栏弹窗一致。

### 4. 设计令牌单一来源 + 漂移门禁

令牌抽到 `web/tokens.css` 作唯一来源,`desktop/ui/tokens.css` 是它的副本,
`make desktop-check` 用 `diff` 卡住漂移。纯格式化函数同样处理(`web/format-core.js`)。

**为什么是「副本 + 门禁」而不是打包器**:项目至今没有任何前端构建步骤,
ADR-0002 与 ADR-0010 都刻意维持这一点;为了共享一个 CSS 变量块引入打包器,代价
远大于收益。也不用符号链接 —— `tauri-build` 嵌入前端资产时是否跟随符号链接没有
保证,而一个平台相关的构建行为不值得赌。

副本的问题从来不是「有副本」,是**没人发现副本变了**。上面那句失效的注释就是证据。
`fmt-check` 已经在项目里立过这个规矩:能自动核对的约定,就不要靠人记住。

### 5. 弹窗内容扩到实时视图(修订 ADR-0008 第 4 条)

ADR-0008 写「菜单栏 v1 是精简视图(配额、燃烧速率、今日用量),不是九页面板的搬运」。
后半句仍然对,前半句的清单要改:**生成速度进来**,与燃烧速率、今日用量并列;
再加一行会话/设备摘要。

依据是 M5 的重定优先级:速度(F15)与实时会话(F25)升为 P0,配额(F19)降为 P2。
v1 那份清单是在旧优先级下开的 —— 把 P0 指标留在浏览器里、P2 指标放上菜单栏,
恰好是反的。

**「不是九页面板的搬运」这条边界不动**:统计、报表、明细、热力图仍然只在浏览器里。
菜单栏答的是「此刻怎么样」,不是「这个月怎么样」。

### 6. 弹窗不引图表库

配额环形表盘与 sparkline 手绘 SVG。ADR-0010 允许 vendored 预构建库,但那是为了
九页面板上真正的多系列图表;在一个 340px 宽的弹窗里,ECharts 约 1MB 的资产换不回
对应的表达力。

表盘复用托盘图标生成脚本的几何(起 135°、扫 270°、描边 0.145),于是托盘图标、
应用图标、弹窗表盘是同一个形象的三种尺寸,而不是三个各画一遍的圆。

## 后果

**正面**

- 菜单栏数字与浏览器面板来自同一条流的同一个快照,滞后从 15–60s 降到秒级;
- 请求数减半(两条轮询 → 一条流);
- 退出、自启、打开面板这些下限功能补齐;
- 令牌与格式化只有一份定义,再脱节会在 `make desktop-check` 里失败,而不是靠人发现;
- 服务端零改动。

**负面**

- 引入四个 Tauri 插件(autostart / notification / opener / global-shortcut)与
  `eventsource-stream`。桌面端的依赖面明显变宽,而它已经是项目里第三套工具链
  (ADR-0008 认下的那笔负债)。接受的前提仍是**桌面端不承担采集职责** ——
  这些都是展示与交互,没有一个碰写入路径。
- 长连接是新的状态机:连接、断流、退避、切服务端时取消。轮询没有这些分支,
  代价是必须为它写单测,并且**降级状态一定要在 UI 上可见** —— 一条静默失败的流
  比轮询危险得多,它会让一个冻住的数字看起来一切正常。
- `windowEffects` 与 `macos-private-api` 一样把 Mac App Store 排除在外。这与
  ADR-0008 已经做过的选择一致(经 GitHub Releases 分发),不是新代价。
- `set_title` 在 Windows 上不支持。Windows 端本就未排期,届时该项降级为不可用,
  不是阻塞项。

**不在本 ADR 范围**

- 自动更新(需要签名密钥与更新服务器,单独决策);
- Windows 端的托盘行为与视觉验收 —— 仍沿用 ADR-0008 的「先 macOS」。
