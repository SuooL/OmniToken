# ADR-0022 卡片头部:标题在前,口径作后缀

状态:已采纳(2026-07-31,与用户确认)

## 背景

用户反馈「几乎每一个 panel 的 section title 和里面的具体名字字号都不一致」,
举例:「共享时间轴 · 独立零基线」下面的「五小时来源速度贡献」明显更大。

实测九个路由、六十余个卡片头(浏览器 computed style):

| 元素 | 字号 / 字重 | 一致性 |
|---|---|---|
| `.card-head h2` | 14px / 600 | 全站一致 |
| `.eyebrow` | 11px / 400 | 全站一致 |
| `.subtle` | 12px | 全站一致 |

**所以「到处不一致」这个判断不成立** —— 但用户的不适是真实的,原因不在字号统一性,
而在**信息层级与视觉层级相反**:

- `eyebrow` 排在**上方**,读起来像小节标题,却是最小号(11px);
- `h2` 排在**下方**,却是最大号(14px)。

眼睛先看到上面那行小字,再看到下面更大的字,于是「下面那个明显是大的」。
这不是字号错了,是**顺序错了**。

同轮实测还查出两处客观缺陷,一并处理(见「顺带修掉的两个 bug」)。

## 决策

**1. 标题在前,口径作为同行后缀。**

```
旧:  共享时间轴 · 独立零基线        ← 11px,在上
     五小时来源速度贡献              ← 14px,在下

新:  五小时来源速度贡献 共享时间轴 · 独立零基线
     ← 14px          ← 11px,同一行、跟在后面
```

视觉顺序与信息顺序从此一致:先说这张卡是什么,再补它的口径。字号大小与阅读
先后不再打架,也就不需要靠调字号去掩盖顺序问题 —— 那只会把 27% 的落差改小,
反差还在。

`.eyebrow` 不再 `text-transform: uppercase`:它现在紧跟中文标题,大写变换对中文
无效、对其中夹带的英文标识符(如 `contribution_tps`)反而有害。

**2. `h2` 的默认字号改为 14px。**

原来基础规则是 `h2 { font-size: 13px }`,靠 `.card > h2, .card-head h2 { 14px }`
覆盖。**没包在 `.card-head` 里的 h2 就漏到 13px** —— 实测四处:缓存页「按模型」
「每日命中率」、设备页「设备明细」、模型页「模型明细」。

改基础值而不是给这四处补 `.card-head`:让默认就是对的,新写的卡片不必记得包一层
才不出错。这与「覆盖率门禁只卡关键包」是同一种取向 —— 能靠机制保证的,不要靠
人记得。

## 顺带修掉的两个 bug

**热力图文字缩放。** SVG 的 `viewBox` 宽 775 单位,却以 `width:100%` 拉伸到
1331px 渲染 —— 缩放系数 **1.72×**,于是 `viewBox` 内声明的 11px 文字实际显示成
**≈19px**,而它周围所有标签都是 11–12px。移动端反向:390px 下缩成 ≈5.5px。

根因是 #63「让年度热力图填满卡片」:拉伸让格子填满了卡片,但 `viewBox` 里的
文字跟着一起缩放了。

改为**按容器宽度反推格子尺寸**,使 1 viewBox 单位 = 1 CSS 像素。这样文字、圆角、
间距全部按声明值渲染,不需要为每个新元素再算一次反向缩放系数。配 `ResizeObserver`
在容器变宽窄时重绘。格子尺寸取 7–22px:上限按 1440px 页面下卡片能被填满来定
(实测需要 21px),下限保证窄屏下方块仍读得出是日历。

## 代价与边界

- **改的是排版,不是数据。** 文案一字未动,只换了位置与默认字号。
- **`.eyebrow` 与 `.metric-card .metric-label` 原本共用一条规则**,本次拆开 ——
  后者仍是块级小标签(指标卡里它在数字上方是对的,那里没有顺序倒置问题)。
- **热力图不再无级拉伸**,格子尺寸按容器分档。极窄容器下有下限,低于下限时
  横向滚动,不再把文字压到不可读。
