# ADR-0024 口径说明收进 `i`,行动指引留在原地

状态:已采纳(2026-08-01,与用户确认)

## 背景

用户反馈:「按模型 · 近 30 天 下面那一大堆的文字说明不需要,页面内很多地方都不要
直接显示这么多文字说明,你可以显示一个 i info 符号,鼠标点击或放上去显示提示框。」

面板上这类说明是**方法论**:速度怎么算的、为什么不给逐条中位数、未知通道为什么
不摊分。它们的共同点是**读一次就够**,而写成正文的代价是每次渲染都要付:

| 位置 | 长度 |
|---|---|
| 速度页「按模型」上方 | 六行,把它所描述的那张表推到首屏之外 |
| 速度页「来源速度贡献」下方 | 两行 |
| 速度页曲线下方 | 一行 |
| 速度页「本地代理」上方 | 两行 |
| 总览页计费通道下方 | 一行 |

最长的那段尤其说明问题:一段解释表格怎么算的文字,把那张表挤出了首屏。

## 决策

### 1. 判据:解释「怎么算」的收起来,说明「这是什么」「该去做什么」的留下

这条界线必须能执行,否则下一个写卡片的人只能猜。三类各归各位:

- **口径 / 方法论** —— 「速度 = Σ输出 tokens ÷ 生成区间并集」「未知通道不摊分」。
  收进 `i`。读者第一次需要,之后不需要。
- **正在读的这个数是什么** —— 「每 60 秒一个点」「另有 3 个模型,见下方明细表」。
  留在原地。它描述的是眼前这一屏,不是背景知识。
- **行动指引** —— 空状态里的「配置 agent 的 `proxy_listen` …」。留在原地,
  **这是本决策唯一的硬约束**:把「怎么打开这个功能」藏进图标,等于让它不被读到。

### 2. 点击开合,不是纯 hover

hover 在触屏上没有对应动作,一个在手机上打不开的提示框等于没有。所以主交互是
点击;`i` 是真正的 `<button>`,因此自动进入 tab 顺序、自动响应 Enter 与空格,
不需要为键盘另写一套。Escape 关闭,点击别处关闭,同时只开一个。

### 3. 事件委托,不逐个绑定

各视图每次轮询都重建 `innerHTML`,绑在按钮上的监听器会随之丢失。所以监听装在
`document` 上,只装一次。

### 4. 不动表单帮助文字

设置页那些「清空输入框即取消重命名」是填表时要同时看着的,与本决策无关。

## 影响

- 新增 `web/infotip.js` 与配套样式,`web/*.js` 的 embed glob 自动收录,
  只需在 `index.html` 加一行 `<script>`;
- 速度页四处、总览页一处口径说明改为折叠,`speed-curve-legend` 与
  `speed-model-note` 两个容器随之删除;
- 契约测试钉住两个方向:口径说明不得退回正文,空状态指引不得被折叠。

## 未决

其余页面(报表、缓存、明细)的说明本轮没动 —— 它们目前都是一句话的「这是什么」,
按第 1 节的判据本就该留在原地。将来若又长起来,判据已经在这里了。
