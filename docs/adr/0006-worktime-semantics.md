# ADR-0006 工作时长语义:事件区间化 + 双指标(投入/代理运转)

状态:已采纳(2026-07-27,与用户确认)。修订初版实现(纯完成点 5 分钟折叠)。

## 背景

初版把 usage 事件当作时间点做 5 分钟间隙折叠,存在三个缺陷:
①长流式输出/长推理(单次 >5 分钟)被误判为空闲丢弃——模型在干活的时间反而不算;
②"5 分钟停表"规则本应只作用于"回复完成→下一条用户指令"的人类思考期,
却被无差别用于一切间隙;③同 repo 并发会话的时间合成语义未定义(1h 并行算 1h 还是 2h)。

## 决策

1. **事件区间化(解析层)**:解析器跟踪会话文件内上一行**任意**事件的时间戳
   (用户消息、工具结果、assistant 完成皆有 timestamp),为每条 usage 事件记录
   `duration_ms = ts − prevTS`(clamp 至 [0, 30min] 防时钟异常)。
   事件从时间点变为区间 `[ts − duration, ts]`,长生成被精确覆盖。
   该值同时是日志通道的"模型侧用时"近似(M3 代理通道给精确值 + TTFT)。
2. **会话内合成**:同一 (device, session, repo) 的区间按序桥接——间隙 ≤ 阈值
   (`worktime_idle_minutes`,默认 5)计入(人类阅读/打字期),> 阈值停表在
   前一区间末尾、在下一区间重新开表。产物:每会话的活跃时间段序列
   (也是明细页时间线/甘特视图的数据基础)。
3. **repo 汇总双指标**(并发语义,与用户确认):
   - **投入时长 union**:该 repo 全部会话(跨设备)时间段的并集——墙钟时间,
     永不重复计数,回答"我在这个项目上花了多久";
   - **代理运转时长 sum**:各会话活跃时长直接相加——回答"AI 为这个项目跑了多少",
     sum/union 即并行度。
   面板默认展示 union,sum 显著大于 union 时附注。
4. 仍为查询时纯派生,不新增表、不引入采集端状态。

## 后果

- event_id 不变(duration 不参与 ID),幂等不受影响;已入库历史事件 duration=0,
  须重建库全量重扫回填(秒级);
- Claude Code 增量续读时,批次首事件的 prevTS 不可得,duration 记 0,
  由会话内桥接规则近似覆盖(误差 ≤ 一个间隙,可接受,不为此持久化解析器上下文);
- 解析器需读取每行的 timestamp(非 usage 行仅做轻量提取,不全量反序列化)。
