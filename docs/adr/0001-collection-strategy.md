# ADR-0001 采集策略:日志解析为主、本地代理为辅

状态:已采纳(2026-07-26)

## 背景

三种候选:①中心网关代理(one-api/LiteLLM 式)②本地日志解析 ③官方用量 API。

## 决策

以 **本地日志解析** 为主通道,**agent 内置本地代理** 为辅(M3,采集 API 直调与精确速度),
不采用中心网关,不依赖官方用量 API(无设备维度、不含订阅用量)。

## 理由

- 订阅制用量(Claude Max 等无 API key 场景)只有日志可得;
- 不碰请求链路:零延迟、零单点故障——中心网关挂掉会阻断所有设备的工作;
- 日志含完整明细(cache 分量、cwd、branch、时间戳),信息量不低于网关观测;
- API 直调不写日志,是日志方案唯一盲区 → 用"每设备本地代理"补齐,
  保持无中心单点的性质(代理挂了只影响本机直调脚本)。

## 后果

- 需为每种工具维护解析器(用 Strategy 插件边界控制成本,并以 ccusage 为语义参照);
- tokens/sec 在日志通道只能近似,精确值依赖代理通道(面板须区分标注)。
