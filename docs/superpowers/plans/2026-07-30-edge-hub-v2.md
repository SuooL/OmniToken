# Edge Hub v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide authenticated device identity, durable at-least-once delivery, explicit acknowledgements, heartbeat-based liveness, and safe LAN/SSH/public deployment guidance while keeping one authoritative central database.

**Architecture:** Each edge agent owns a stable UUID, device-scoped bearer credential, and local SQLite outbox. The hub validates a versioned envelope, binds payload identity to the credential, applies idempotent events transactionally, returns an explicit ack, and records server-received heartbeats.

**Tech Stack:** Go 1.26, `net/http`, `database/sql`, modernc SQLite.

## Global Constraints

- The central hub is the only authoritative analytics database.
- Preserve `event_id` idempotency and the existing allowed attribution upgrades.
- V1 `/api/v1/ingest` remains available during migration.
- Public exposure requires HTTPS or an encrypted overlay; plaintext non-loopback agents require explicit opt-in.
- Agent batches advance only after a validated v2 acknowledgement.
