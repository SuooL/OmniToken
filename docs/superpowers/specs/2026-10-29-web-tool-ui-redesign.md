# Web 工具界面重构设计与实施方案

状态：用户于 2026-10-29 授权细化方案并实施；Web 生产部署不在本次范围。
基线：origin/dev 2785ed3（2026-10-29）。桌面采用 ADR-0037 已确认标准。

## 结论与检查范围

保留原生 JavaScript、Go embed、ECharts 和现有九条路由；不需要引入 React、重写
后端或把所有页面搬进侧栏。主要工作是重新分配信息层级、统一视觉/状态组件和下钻。

已阅读九页渲染代码、共享样式/格式化、路由、遥测缓存、ChartRegistry 和设置权限
流程，并在隔离本地 Hub 中以 2700 条合成元数据事件浏览全部九页，检查 1440px 与
420px 两种视口，共 18 个页面状态，无 pageerror 和整页横向溢出。合成数据不代表
生产用量；此检查不涉及修改现网、真实凭据或患者/对话数据。

## 需要先修复的语义和交互问题

1. **官方 0% 和零余量被 truthiness 吞掉。** web/live.js 的 renderWindows 用
   `w.authoritative && w.used_percent` 判断读数，用 `w.remaining_tokens` 判断余量。
   以 authoritative=true、used_percent=0、tokens=16M、remaining_tokens=0 直接调用
   当前渲染函数，得到：官方 0% 未显示、零余量未显示、进度条回落为 20%（tokens/80M）。
   这是已复现的显示错误，优先于美化：用 Number.isFinite 判定存在性；缺失不画
   百分比进度条；官方窗口零/满/超额/未知分别测试；保留 5h 受周窗口约束。
2. **来源颜色不一致。** overview/live 用来源语义色，modelsview.js 的 sourceSeries
   却按通用 --series-1..4 取色。同一份 fixture 中 Claude 在总览为橙、模型页为蓝；
   DeepSeek 在总览为青绿、模型页为粉色。建立一个 SourceIdentity 映射，所有页面
   及图例、表格、图标共用。来源、模型序列、计费通道、风险为不同语义，不共用取色器。
3. **外观说明与实现不一致。** settingsview.js 写“主题跟随系统”，tokens.css 明确
   dark-only。当前先统一为已实现的深色主题说明；若以后支持浅色，作为独立外观任务，
   包含全图表、控件及状态验证，不在此重构中承诺未实现功能。
4. **定时刷新替换整页 DOM。** Overview.render 与 CacheView.render 重设 root.innerHTML；
   前者每 30s 更新，可能重建图表、折叠状态及焦点目标。参考 Devices/Models 已有
   shell-once 模式，初始化结构一次、后续仅更新数据；保留焦点、滚动、折叠和选择。
   这一项的风险由代码确认，具体用户状态丢失需要专门浏览器回归量化。
5. **表达口径混杂。** 总览首屏混今日总量、来源构成、来源总量、设备数量，下面又混
   当日趋势、近 10m 贡献、30 天设备与计费、365 天活动。时间范围必须在对应区域
   直接可见，不能用一个全局筛选暗示所有区块共用口径。

## 统一设计语言

沿用桌面已经确认的“工具界面”标准：平静背景、清楚行列、有限强调。

- **外观 profile：** web/tokens.css 的 tool-* 已随桌面加入，但本次 Web 页面仍用旧
  A4 profile。下一步在 Web 根节点启用 tool profile，保留原 CSS fallback 渐进迁移。
  只保留页面外框及必要独立区域，列表/表格靠细分隔线分组，避免卡片套卡片。
- **字号与密度：** 正文 13–14px，辅助 12px，表格可用 12–13px；主要值适度放大，
  一个区域只有一个主数字。系统字体正文，数字 tabular-nums，单位和精度统一。
- **来源：** Claude 暖橙图标、Codex 中性浅色图标、DeepSeek 蓝色图标，列表与图表
  共用映射。仅在识别、选中态和图形上强调，大面积背景保持低饱和。
- **风险：** 配额正常青绿、70% 黄、80% 橙、90% 红。读数、条形与文字状态同步；
  超额保留实际数字，条长封顶。风险判断用未舍入值，0、null、过期分别表达。
- **操作：** 所有可展开行整行可点，有可见的悬停、选中及键盘焦点；纯展示行没有
  箭头和伪按钮。图标用于识别功能，不给每个小标签堆图标。涨跌保持中性。
- **技术说明：** contribution_tps/native_tps、Fleet coverage 等技术标识改为清楚的
  中文业务标签；必要解释用现有 infoTip，不能把完整算法段落放在图表标题里。

## 页面分工与布局

### 总览：用量、风险、趋势

首屏三块：今日总量与比较摘要；来源纵向列表/简短构成条；Claude/Codex 双窗口
官方配额表。下方一张主要历史用量趋势图。来源点击打开模型明细抽屉，设备摘要
点击进入设备页；计费通道、今日模型、365 天热图等作为分析区域，默认收起或明确
跳转对应页面。移除“总量 + 来源构成卡 + 三个来源数字卡”同层重复展示。

今日用量来自 telemetry.today，时间边界取服务端时区。历史用量趋势可以消费现有
reports/daily 或 overview 数据；需要先核对 payload 是否覆盖对应时段，再决定 API
适配，不能把速度趋势改标题充当用量趋势。总览不再重复完整实时速度诊断。

### 实时：现在发生什么

顶部一行已测总速度、贡献会话/设备数、连接新鲜度。主区保留并发时间线与会话
列表，便于识别是谁在工作。分来源 60m 趋势缩成可展开诊断，详细比较由速度页
负责。配额移至首屏侧栏或顶部紧凑表格，避免必须滚到最底才看到周额度紧张。

设备在线、进程打开和最近花费 tokens 分开命名。没有进程上报显示“会话状态不可
观测”，不显示“没有会话”。非订阅通道只有用量/成本，不画额度百分比或配额条。
原有窗口末外推保留为“估算详情”，默认不与官方读数抢主位。

### 速度：解释和比较速度

顶部复用与实时页同一快照和测量覆盖摘要。主图为来源贡献趋势、统一零基线与
可比较尺度。下方一个模型比较表：贡献速度、自身速度、覆盖、测量类型、样本
数量；代理精确测量和日志推算保留独立分组，不合并为一个“更好看”的排名。

当前两组时间趋势的用途需要明确：近 60m 的实时趋势与近 30 天模型比较各有标签。
未知/无测量保持为空或缺测带，不能补零；空闲和掉线也不能共用一条零线。

### 明细：表格优先

顶部紧凑筛选条 + 已选条件摘要；主体首先是分页事件表，时间、设备、来源/模型、
输入、输出、缓存、成本列对齐。当前 260px“当前页分布”移到默认收起的分析区域，
明确仅覆盖当前页，不代表全部筛选结果。点击事件打开侧栏看其余元数据。

保留后端分页（当前 limit=100），不新增全量下载；筛选变化回第一页。URL 同步
设备、来源、模型、项目、session、days、分页等必要状态，返回时恢复上下文；当前
路由只显式处理 session，不能宣称全部筛选已可分享。

### 报表：筛选、趋势、数据导出

粒度/范围/导出收在一个工具栏，选中态与禁用态统一。趋势图适当收紧，下面主表
右对齐数值，日期/会话标识稳定；点击会话沿用已有明细下钻路由。导出仅导出当前
已选范围，处理中禁重入，失败可重试。没有定价保持“无定价”，不能显示 $0。

### 设备：设备表为中心

首屏为在线/未及时上报/积压摘要与设备表；列包含显示名、活跃状态、最近心跳、
待上报批次、区间 tokens。点击设备打开详情抽屉，内含使用趋势、来源/模型与
会话观测状态。保留现有每日对比图作为可展开分析，只有做比较时才占据大面积。

避免把“本次 API 请求成功”当作“设备刚上报成功”；心跳、采集、上传分别显示。

### 模型：排名表 + 有目的的图形

模型排名表与来源构成条是主体；提供 tokens/成本等已有指标的排序，颜色取稳定
来源映射。当前“成本 / token”散点图默认为折叠分析工具，而非每次访问必经。
fixture 中所有模型 tokens 相同，log 轴仍跨多数量级并产生大面积空白；需显式按
有效数据求 domain，加合理边距，并处理 x 全相同/单点/无价格等退化情况。

模型太多时主图只显示 Top N + 其他，完整表保留所有分页/当前接口范围内模型；
Top 100 接口截断必须明确标注，不能称全库完整模型。

### 缓存：效率与构成

主位显示命中率、输入/缓存构成和可估算节省额；趋势图旁明确分母。模型缓存表
紧随其后，其他构成图默认展开一个、其余按需查看，降低 fixture 中两千多像素
的纵向长度。没有价格时节省金额不可计算，缓存 token 仍可显示；命中率分母为 0
时表达“暂无可计算输入”，不冒充 0% 缓存收益。

### 设置：按任务分组

改为“连接与凭据、定价、设备管理、外观”四组。桌面宽屏使用左侧分组导航，整行
可点击；窄屏使用同页分组或选择器。保留已有草稿保护与字段级保存，错误靠近字段。
设备合并和撤销进入设备管理的“高级操作”折叠区，不在所有设置页面常驻大红卡。
合并预览、手工输入全名、人工确认、权限隔离与审计仍必须完整保留。

## 工程实施

不引入新构建工具；原有文件可直接迁移。先提取少量可复用 helper：

| 文件/模块 | 职责 | 复用现状 |
|---|---|---|
| tokens.css / tool-* | 外观、来源与风险基础令牌 | 桌面已加入并保持同步 |
| 新 source-ui.js | 来源名、logo、颜色、可访问文本 | 收敛各页自己的 SOURCE/LABEL/ORDER |
| 新 quota-ui.js | 官方百分比、风险等级、估算、重置和缺失状态 | 替代 live.js 内多套窗口模板 |
| 新 detail-drawer.js | 单一详情、焦点归还、Esc、窄屏覆盖及滚动 | Web 的 DOM 抽屉，不新建浏览器窗口 |
| format.js | 状态块、精度、范围/时区标签 | 保留 renderState/classifyAPIError |
| telemetry.js + 小型 LiveSnapshotCache | 去重请求、新鲜度、订阅/轮询生命周期 | 复用 TelemetryCache；不要另起第三套数据层 |
| charts.js / ChartRegistry | 稳定图表实例、同色映射、共享轴与缺测 | 保留 ECharts、fallback 表及 ResizeObserver |

先做 source/quota helper 的纯函数测试，再逐页替换。每页 buildShell 一次，updateData
只更新数值、列表及 ECharts.setOption；跨路由离开时取消请求/订阅，沿用 generation
保护。列表按稳定事件/设备身份关联，不能以显示名当主键。错误时保留最后数据并
标注具体更新时刻；全局 Hub 健康不覆盖某张图的数据过期状态。

Web 抽屉宽建议 360–400px，宽屏覆盖在页面右侧并保留主表位置；窄屏覆盖整个内容
区域，有明确返回。避免打开抽屉就挤窄主图、触发全部 ECharts 重排。关闭后焦点
回到原行，重新刷新不丢失当前选择；点击组外关闭遵循已存在的未保存表单保护。

## 分阶段交付与验收

| 阶段 | 内容 | 验收与停止条件 |
|---|---|---|
| P0 | 官方 0/零余量、缺失估算、风险色及主题说明纠正 | 0/null/100/超额/周已满都有回归；不改历史数据/计算口径 |
| P1 | 共用视觉/来源、总览与实时主次、详情抽屉 | 按已确认的桌面工具界面标准实现；1440×900 首屏能识别总量/来源/风险，配额警告不藏在底部 |
| P2 | 表格优先的明细/报表/设备与设置分组 | 筛选/URL/返回/焦点/草稿/导出保持；只在详情需要时加载附加内容 |
| P3 | 模型/缓存图形精简、图表生命周期与请求去重 | 同色跨页一致；退化数据轴合理；定时刷新不重建图表或丢失状态 |

每阶段独立 feature PR → dev，运行 make check 和相应浏览器验收；部署为独立授权
步骤。本次桌面发布不包含把上述 Web 页面设计直接上线。

验收矩阵：无数据、真实零值、部分缺失、401/403、网络失败保留上次数据、20+ 模型、
长名称、100+ 事件分页、过期配额、零剩余、超额、多设备；420/768/1440 视口，键盘
Tab/Enter/Esc、焦点返回、减少动态效果、图表 fallback 与导出范围一致。

保留现有优点：九条路由直接可达、移动端不整页横向溢出、generation 防乱序、last-good
缓存、明细分页、导出错误反馈、图表可读数据表、设置草稿保护及管理动作确认。
重构针对信息与交互，不能以减少页面长度为由破坏这些已有行为。

## 实施补充（2026-10-29）

本方案已按 `plans/2026-10-29-web-tool-ui-implementation.md` 实施，架构决策见
ADR-0038。最终核对后纠正接口范围：`models?top=100` 只限制每日构成的模型，
`by_source` 排名没有该截断；页面分别标注 Top100 每日构成和本次接口返回的排名。
设备接口不提供完整来源/模型历史与采集/上传时间，详情明确标为不可用，不编造。

落地为一个集成 feature PR，内部保留设计计划和实现的 focused commits，而不是
让存在共享依赖的 P0–P3 在互不完整的状态分别自动合并。未部署生产。
